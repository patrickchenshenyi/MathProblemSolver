# 差距分析：本项目 vs OpenAI/Anthropic 数学突破方案

> 版本：v1.0 · 日期：2026-09-27 · 依据：`Related_Works/` 四份研究文档 + 本项目 Phase 0–4 实测
> 一句话结论：**瓶颈不在协作基础设施（已建成且干净），而在缺一个强验收器**。"验收器强度决定自治程度"——整数答案题的验收器只有 L0 格式/范围，太弱，所以多 agent 团队必然退化成"采样 + 聚合"，Phase 4 试点里 C 无正确率收益却付出 6–11× token 是**结构性必然**，不是调参问题。

---

## 1. 一线方案拆解与可迁移成分

| 来源 | 方案要点 | 可迁移到本项目（API-only、无训练） |
|---|---|---|
| Anthropic FLT | 用 AI 做**验证**：Prove2Me 的 DAG、语句/证明分离、proof-sketch、milestones、read-back、Formalpedia；Lean + comparator + 公理审计 + nanoda | ✅ 几乎全部（开源验证层与协作机制，无需训练） |
| Anthropic RH | validator 互审 + 反例搜索 + 独立重证 | ✅ 全部（critic 可升级为此） |
| OpenAI NS | 上万 agent 分组隔离 + RL + 先易后难课程 | ⚠️ 仅"分组隔离 + 课程"可迁移；RL/算力不可 |
| Buckmaster | 人给纲领 → LLM 推关口 → **Lean 先证** | ✅ 最贴近本项目（人+LLM+Lean 的分工） |
| AIMO3 冠军 | 纯推理工程：无微调、熵加权采样、早停 | ✅ 已具备基础（采样/预算），可补早停与加权 |

## 2. 维度差距

| 维度 | 现状 | 差距 | 可补？ |
|---|---|---|---|
| **验证强度** | 仅 L0 格式验收；Lean 只留接口（T2） | **最大差距** | ✅ 可补（方案已定稿：`Lean_Verification_Plan.md`） |
| 搜索机制 | 每子问题 ≤3 策略副本、无搜索树 | 中 | ⚠️ 部分可补（早停/加权/课程） |
| 纠错循环 | 无 validator/反例/重证；critic 只报告 | 大 | ✅ 可补（critic 升级为反例搜索 + 独立重证） |
| 数据飞轮 | 无 | 大 | ⚠️ 只能做"诊断型"（失败样本标注，不训练） |
| 训练（RL/SFT） | 无管线 | 硬边界 | ❌ 不可补（API-only） |

**关键分界**：所有一线方案里能搬的东西几乎都在**验证层与协作机制**；而本项目恰恰在验证层最弱。这正是"先造验收器、再堆 agent"总原则的再次印证。

## 3. 优先级建议（结合"解单模型解不出的难题"目标）

| 优先级 | 事项 | 理由 |
|---|---|---|
| **P0** | "全资源直接干"改**按需扩张**（默认 1 solver，无进展/critic 报错时才扩张）+ 全量评测跑完 | 试点已证全资源开干在可解对题上是纯浪费 |
| **P1** | 建"**单次上下文装不下**"的难题集（含 AIMO3 ref P2：历史上最新 DeepSeek 推理模式 3 次全炸上下文） | 团队的主场；P2 基准已在跑 |
| **P2** | **提前 Lean，且定位 = 中间子任务推导的验收**（`submit_task` 的 `lean` 字段启用，对应 Prove2Me 的 proof-sketch 思想），而非只验最终整数答案 | **唯一实质杠杆**：整数答案题天然没有强验收器，把 Lean 用在中间步骤才能让"验收器强度"覆盖求解过程 |
| **P3** | critic 升级：反例搜索 + 独立重证（RH 式） | 补纠错循环 |
| **P4** | 评测严谨化：多次运行报方差、失败样本诊断标注、"已验证 ≠ 已解决"、"编译通过 ≠ 定理成立"等口径纪律 | 避免自欺 |

## 4. Prove2Me / flt 评估层的具体启示

**Prove2Me**（可直接映射到本项目的四个机制）：
1. **保留已通过副本的成果供复用**（不丢弃 loser 的中间成果——我们 T3 只 interrupt 不销毁成果消息，但可做得更显式）；
2. **milestones 锚点**：把题面约束逐字写进任务描述（我们现在是"验收标准"自然语言，可升级为逐条可核对的里程碑）；
3. **read-back 反向复述**：让 agent 复述它理解的题面，防止语句漂移（防"翻错题"）；
4. **人只审核心**：人工审查只花在最关键命题上（对应我们 L2 的人审范围）。

**flt-navier-stokes-evaluation-layer**（验收器"四件套"铁律）：
- **公理审计**（禁 sorry/axiom/native_decide 等四条"AI 骗过内核"路线）——已写入 Lean 方案的铁律；
- **语句对齐（comparator）**——题面形式化必须与原文逐字对齐（对应 L2 人审 + sanity）；
- **版本对齐**（钉 Lean/mathlib 版本）——已写入 Lean 方案 L0；
- **独立内核重放（nanoda）**——终极保险，后置；
- 两条教训：**"编译通过 ≠ 定理成立"**（Collatz 双内核同时被骗）、**"已验证 ≠ 已解决"**。
